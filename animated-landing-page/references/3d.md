# 3D — animation (plays on its own) & interaction (follows the pointer)

Two ladders. **Interaction (B)** is cheap and safe: pointer-driven transforms on DOM
elements, no libraries. **Animation (A)** ranges from CSS keyframes to a full WebGL tier.
Start at the lowest rung that satisfies the brief — every rung below still ships.

## CSS 3D cheatsheet

| Property | Role |
|---|---|
| `perspective: 1200px` | on the **scene parent** — how strong the depth reads. Lower = more dramatic. |
| `transform-style: preserve-3d` | on children that must live in 3D space (keeps their children unflattened) |
| `transform: rotateX/Y/Z(), translateZ()` | the transforms themselves |
| `backface-visibility: hidden` | required for flip cards (stops the mirrored back showing through) |
| `transform-origin` | pivot point; default center — offset for card flips from an edge |
| `will-change: transform` | **sparingly**, only while a heavy element is actually animating |

Common mistakes: `preserve-3d` on the same element as `overflow: hidden` (forces flattening
in most browsers), missing `perspective` on the parent (children render flat — the classic
"my 3D does nothing" bug), and putting `perspective` on the transformed element itself.

## B1 · Pointer tilt card → `templates/TiltCard.tsx`

The signature effect. Wrapper carries `perspective`; the card rotates toward the pointer;
a specular glare follows. Template handles rAF smoothing, touch gating, reduced motion,
and cleanup.

```tsx
<TiltCard maxTilt={10} scale={1.02} glare className="card p-6">
  <h3>Plan</h3>
</TiltCard>
```

Internals worth knowing (all in the template):

- Pointer position → normalized `-0.5…0.5` from `getBoundingClientRect()` →
  `rotateY = nx * maxTilt`, `rotateX = -ny * maxTilt` (**inverted X**: card tilts *away*
  from the pressed side, like a physical object).
- **Smoothing:** write `node.style.transform` inside a rAF lerp loop (`c += (t - c) * 0.12`);
  raw pointer→transform is jittery. No React state in the loop — zero re-renders.
- **Glare:** `radial-gradient` at `--gx/--gy` percentages tracking the pointer; cheap and
  sells the material.
- **Gates:** `(hover: hover) and (pointer: fine)` and not `(prefers-reduced-motion: reduce)`;
  otherwise render the static card.
- Keep tilt off elements containing links/text selection if `maxTilt` > ~12° — readability.

## B2 · Flip card (click/tap/Enter to reveal)

```tsx
<button type="button" onClick={() => setFlipped(!flipped)} aria-pressed={flipped}
  className="group [perspective:1200px] text-left">
  <div className="relative h-64 w-full transition-transform duration-700 [transform-style:preserve-3d]
    [.group[aria-pressed=true]_&]:[transform:rotateY(180deg)]
    [.group:hover_&]:[transform:rotateY(180deg)] motion-reduce:transition-none">
    <div className="absolute inset-0 [backface-visibility:hidden] card p-6">{front}</div>
    <div className="absolute inset-0 [backface-visibility:hidden] card p-6 [transform:rotateY(180deg)]">{back}</div>
  </div>
</button>
```

Notes: real `<button>` + `aria-pressed` so keyboard works (hover-only flips are inaccessible);
arbitrary-variant syntax (`[...]`) shown for Tailwind 3 — in a JS-heavy version prefer inline
`style` + state. **Never put the only copy of important info on the back face** — or mirror it
in the DOM for screen readers regardless of state.

## B3 · Pointer parallax (hero depth layers)

Layers shift at different rates — depth without true 3D rotation.

```tsx
const onMove = (e: React.PointerEvent<HTMLDivElement>) => {
  const r = e.currentTarget.getBoundingClientRect();
  const nx = (e.clientX - r.left) / r.width - 0.5;    // -0.5 … 0.5
  const ny = (e.clientY - r.top) / r.height - 0.5;
  e.currentTarget.style.setProperty('--px', String(nx));
  e.currentTarget.style.setProperty('--py', String(ny));
};
// CSS vars → transforms; depth factor per layer:
// .layer-1 { transform: translate3d(calc(var(--px,0) * -8px), calc(var(--py,0) * -8px), 0); }
// .layer-2 { transform: translate3d(calc(var(--px,0) * 20px), calc(var(--py,0) * 14px), 0); }
```

Write vars on pointermove (no re-render); CSS does the interpolation — add
`transition: transform 300ms ease-out` per layer for lag-based depth. Depth ratios like
`-8px / 20px / 44px` (background moves *opposite* and slower, foreground more) read as space.

## B4 · Drag-to-rotate

framer-motion (only if already in the bundle — it's ~40KB):

```tsx
const x = useMotionValue(0);
const rotate = useTransform(x, [-220, 220], [-12, 12]);
<motion.div style={{ x, rotate }} drag="x" dragConstraints={{ left: 0, right: 0 }}
  dragElastic={0.9} dragMomentum={false} />
```

Vanilla alternative: `onPointerDown/Move/Up` with `setPointerCapture` writing
`rotateY` from deltaX — same pattern as TiltCard with a persistent accumulator.
Add keyboard support (arrow keys rotate) for accessibility.

## A1 · Layered depth scene

A `preserve-3d` container with children at different `translateZ`, given a slow idle drift:

```css
.scene { perspective: 1000px; transform-style: preserve-3d; }
.scene > * { transform-style: preserve-3d; }
.scene .far  { transform: translateZ(-160px) scale(1.18); }  /* scale back: translateZ shrinks */
.scene .mid  { transform: translateZ(-60px); }
.scene .near { transform: translateZ(40px); }
@keyframes scene-drift { 0%,100% { transform: translateZ(0) rotateX(0deg); }
                         50%     { transform: translateZ(24px) rotateX(2.5deg); } }
```

Elements pushed back must be `scale()`d up (perspective shrinks them) — compute
`scale = (perspective - z) / perspective`. Static depth layers + the B3 pointer handler is
usually enough; reserve full scenes for the hero.

## A2 · Scroll-driven 3D

Section tilts into place as it enters the viewport.

**CSS-native (Chrome/Edge/Safari 26+, Firefox 143+)** — zero JS, degrades to no animation:

```css
@keyframes tilt-in { from { opacity: 0; transform: rotateX(14deg) translateZ(-60px); }
                     to   { opacity: 1; transform: none; } }
.tilt-in { animation: tilt-in linear both;
  animation-timeline: view(); animation-range: entry 0% cover 30%; }
```

**Universal (JS) fallback** — reuse the `Reveal` machinery: an IntersectionObserver adds a
class, CSS carries the transition (same transition-on-added-class trick):

```css
.reveal-3d { opacity: 0; transform: perspective(1000px) rotateX(10deg) translateY(40px); }
.reveal-3d.is-revealed { opacity: 1; transform: none;
  transition: opacity 700ms cubic-bezier(.22,1,.36,1), transform 700ms cubic-bezier(.22,1,.36,1); }
```

For continuous scroll-*linked* motion (rotate proportional to scroll position) use
`useScroll`/`useTransform` (framer-motion) or a throttled `scroll` listener writing CSS vars.
Guard everything with reduced motion; one linked element per section max.

## A3 · 3D carousel / ring

```css
.ring { perspective: 1200px; }
.ring__inner { transform-style: preserve-3d; transition: transform 700ms cubic-bezier(.22,1,.36,1); }
/* each item: rotateY(i * step) translateZ(radius) — radius ≈ (itemWidth/2) / tan(π/count) */
```

- Drive rotation from state (`activeIndex * (360 / count)`); never per-frame JS.
- Items off-face: dim with `opacity` when `|i - active| > 1` rather than hiding.
- Controls: prev/next buttons + dots with `aria-label`s; keyboard arrows on the focused
  region; `role="group"` + `aria-roledescription="carousel"`.
- Mobile: below ~640px a 3D ring of cards is hard to use — fall back to a native
  `overflow-x-auto` snap-scroll row (`.no-scrollbar`).

## A4 · Floating objects

```css
@keyframes float-3d { 0%,100% { transform: translate3d(0,0,0) rotate3d(1,1,0,0deg); }
                      50%     { transform: translate3d(0,-16px,0) rotate3d(1,1,0,8deg); } }
.float-slow { animation: float-3d 9s ease-in-out infinite; }
```

Decorative only, `aria-hidden`, different durations (7s/9s/11s) so objects desync.
Infinite + transform → add to the reduced-motion skip block.

## WebGL tier (only with explicit user confirmation)

**When justified:** real 3D geometry the brand depends on (a product model, particle field,
shader backdrop). **Not justified:** what CSS layers already do — depth, tilt, glow.

Stack: `three` + `@react-three/fiber` (+ `@react-three/drei` for helpers).

```tsx
// HeroCanvas.tsx  — client-only, never in the landing bundle statically
'use client';
const HeroCanvas = dynamic(() => import('./HeroCanvas'), { ssr: false, loading: () => <Poster /> });
// Poster = the static CSS hero (A1/B3) — it doubles as reduced-motion & slow-device fallback
```

Rules:

1. **Lazy-load** with `next/dynamic` + `ssr: false`; the poster renders first and *is* the
   reduced-motion experience — under `(prefers-reduced-motion: reduce)` never mount the canvas.
2. `dpr={[1, 1.5]}` (clamp — mobile dpr 3 tanks fill-rate); `frameloop="demand"` for
   static-ish scenes; pause rendering when the canvas leaves the viewport (IO + `frameloop` toggle).
3. No `filter: blur()` post-processing on full-bleed canvases; antialias off on mobile.
4. Content lives in DOM above the canvas — canvas is `aria-hidden`, `pointer-events` only if
   it's genuinely interactive.
5. Bundle cost: `three` ≈ 150KB min+gz. It must be its own dynamic chunk; verify the landing
   route's first-load JS didn't balloon (`npm run build` output).
6. `will-change`/`transform-style: preserve-3d` never on the canvas container — mixing DOM 3D
   compositing with WebGL layers causes artifacts.

## Choosing a rung

| Ask | Use |
|---|---|
| "Make cards feel 3D / interactive" | B1 (TiltCard) ± B2 |
| "Hero feels flat" | B3 parallax + A1 depth, cheap and safe |
| "Cool scroll experience" | A2 (CSS `view()` timeline, JS fallback) |
| "Showcase a product object" | A3 ring, or WebGL tier if it's real geometry |
| "Impress me" (budget-conscious) | B1 + A2 + M-set — most perceived polish per KB |

## Universal gates (apply to every option in this file)

- Pointer effects: `(hover: hover) and (pointer: fine)` — touch gets the static experience.
- All motion: reduced-motion bail-out (CSS block **and** JS check).
- rAF loops stop when settled and are cancelled on unmount; observers disconnect after firing.
- No content may depend on a 3D state (flipped/rotated) to be readable — DOM keeps a
  linear, no-JS-visible reading order.
